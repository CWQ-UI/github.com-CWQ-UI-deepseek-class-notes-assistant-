### 核心内容

- **一、三次握手回顾（各步作用）**
  - 第一次握手：客户端发送 SYN（转写中后续补充：该报文还携带初始序列号 ISN）。
  - 第二次握手：服务端收到 SYN 之后，回复一个 SYN 加 ACK，即把 SYN 和 ACK 都发回来，表示「我收到了，而且我也准备好了」。
  - 第三次握手：客户端再发一个 ACK（确认）。
  - 到此连接就建立了。
  - **提问（生）**：第二次握手是不是服务端把 SYN 和 ACK 都发回来？ → **解答（师）**：对，就是服务端收到 SYN 后回复 SYN + ACK。
  - **提问（生）**：第三次是客户端再发一个 ACK？ → **解答（师）**：对，客户端再发一个确认，这样连接就建立了。

- **二、为什么需要三次握手（两次为什么不行）**
  - 如果只有两次握手，服务端无法确认客户端收到了自己的 SYN。
  - 旧的、延迟的 SYN 包可能导致服务端建立无效连接。
  - 上述情况称为历史连接（转写原文「这个就叫 额 历史连接」）。
  - 教师明确强调：这是重点，考试会考。

- **三、第一次握手携带的初始序列号（ISN）**
  - 第一次握手客户端发 SYN 时，会带一个初始序列号，叫 ISN。
  - 该序列号是随机的，不能固定。
  - 如果固定，容易被攻击。
