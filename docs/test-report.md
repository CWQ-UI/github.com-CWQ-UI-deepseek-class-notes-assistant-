**已测**：把配置文件中那一份 persona 文本**逐字复制**后作为系统提示词，对 4 个样例运行真实模型推理，检验其整理逻辑、输出结构与信息不足分支是否符合规格。

### 正例 1：正常课堂笔记转写

**输入**：二叉搜索树（BST）讲解转写，含口语填充词（呃/那个/嗯）、重复（「二叉搜索数」）、误识别（「平衡因子」语境），并且**不含任何考点强调信号**。

**关键检验点**：

| 检验点 | 结果 |
|---|---|
| 纠错：`二叉搜索数` → 二叉搜索树（BST） | ✅ |
| 去冗余：呃/那个/嗯 全部清除 | ✅ |
| 结构重组：定义 → 查找 → 复杂度 → 退化原因 → 平衡树，共 5 个板块 | ✅ |
| 保留细节：O(log n)、O(n)、1 2 3 4 5 有序插入例子、高度差不超过 1 全部保留 | ✅ |
| **无强调信号时不臆造考点** | ✅ 原文输出「转写中未出现明确的考点信号。」 |
| 不补充转写外事实 | ✅ 仅提及转写中出现的「第六章」 |
**实际输出（节选）**：

```markdown
### 重点与考点

转写中未出现明确的考点信号。

### 待办与作业

- 课后自行阅读教材第六章。
- 下节课讲树的遍历：前序、中序、后序。
```

### 正例 2：含师生互动的转写

**输入**：TCP 三次握手回顾，含教师点名提问、学生回答、维护课堂秩序用语（「来 上课」「那第三个 同学」），以及一处强调信号「这个是重点 考试会考」。

**关键检验点**：

| 检验点 | 结果 |
|---|---|
| 师生互动**不逐句复述**，合并进知识点 | ✅ 两处问答以「**提问（生）**：…… → **解答（师）**：……」列出 |
| 省略与知识无关的互动（点名、答到、课堂管理） | ✅ 未出现 |
| 提取「这个是重点 考试会考」信号 | ✅ 格式正确 |
| 未过度提取：ISN 由「顺便说一下」引出，无考试信号 | ✅ 未列入考点，仅归入核心内容并加说明 |
| 不确定信息用「（疑似：…）」而非猜测 | ✅ 由习题 3.2 标注「（疑似：第 3 章）」 |

**实际输出（节选）**：

```markdown
### 重点与考点

- **为什么需要三次握手（三次握手的原因、历史连接问题）** —— 教师原话信号：「这个是重点 考试会考」

（ISN 随机的相关内容由「顺便说一下」引出，未出现明确考点信号，已归入上文「核心内容 · 三」。）
```

### 正例 3：含「这个要考」信号的转写

**输入**：线性回归讲解，密集包含 6 类强调信号：`这个要考`、`记住这个`、`必考 一定要背下来`、`注意`、`这里我要强调`、`常考`、`容易错`。

**关键检验点**：

| 检验点 | 结果 |
|---|---|
| 全部信号被识别并归入「重点与考点」 | ✅ 4 条考点 |
| 严格使用规定格式 `- **<知识点>** —— 教师原话信号：「……」` | ✅ 4/4 |
| 信号原话保留，未被改写 | ✅ |
| 公式保留完整（未概括掉） | ✅ `J(θ) = 1/(2m) × Σ[h(xi) − yi]²` |
| 未虚构作业题目与时间 | ✅ 原文「大家回去把作业做了」，仅记原文并注明未说明题目与提交时间 |

**实际输出**：

```markdown
### 重点与考点

- **线性回归的假设函数 h(x) = θ0 + θ1x** —— 教师原话信号：「这个要考 记住这个」
- **均方误差损失函数公式 J(θ) = 1/(2m) × Σ[h(xi) − yi]²** —— 教师原话信号：「这个公式 必考 一定要背下来」
- **学习率大小对收敛的影响（太大震荡不收敛、太小收敛太慢）** —— 教师原话信号：「注意 学习率太大会震荡不收敛 太小收敛太慢」「这里我要强调 这个也是常考的」
- **特征缩放／归一化** —— 教师原话信号：「特征缩放很重要 容易错 忘了归一化的话 梯度下降会很慢」
```

### 边界例：仅约 20 字的极短文本

**输入**：`嗯 今天我们讲一下那个回归 大概就是这样`（去填充词后仅剩「今天讲回归」）

**关键检验点**：

| 检验点 | 结果 |
|---|---|
| 触发「信息不足」分支 | ✅ |
| **未编造**「课堂主题 / 核心内容 / 重点与考点 / 待办与作业」四段内容 | ✅ 明确声明不输出这四部分 |
| 逐条指出缺少什么 | ✅ 5 条：课程主题、具体知识点、教师强调点、作业与安排、师生互动 |
| 提出与 `ask_user_question` 等价的问题 | ✅ 5 条问题清单 || 未把一句话扩写成「看似完整的纪要」 | ✅ |
| 对「回归」一词不作臆测 | ✅ 指出可能是回归分析、回归测试或其他 |

**实际输出（节选）**：

```markdown
### 信息不足：现有内容无法整理成课堂纪要

现有转写只有一句约 20 字的内容：「嗯 今天我们讲一下那个回归 大概就是这样」。它只包含一句开场语，
去口语填充词后仅剩下「今天讲回归」这一条线索，没有出现任何完整的知识点陈述，因此不足以整理出结构化的
课堂纪要。为避免编造，这里不输出「课堂主题 / 核心内容 / 重点与考点 / 待办与作业」四部分内容。

逐条列出缺少的关键信息：
1. **课程主题**：仅能看出与「回归」有关，无法确定课程名、章节名、教师姓名……
2. **具体知识点**：没有出现任何定义、公式、数值、步骤、分类、举例或反例……
（其余 3 条略）
```

> 注：边界例测试时该执行环境未挂载 `ask_user_question` 工具，故按 persona 要求改为等价的「正文问题清单」。**最小重建版预设（persona + tool-fs）也未挂载 `tool-ask-user`**，因此该分支在真实对话中同样依赖运行时容错；仅当你在预设中额外加入 `tool-ask-user` 行时，才会走真实工具调用路径。

## 4. 遗留事项与人工确认步骤

1. 在 GUI 新建会话，Preset 选择器中选择「课堂纪要助手」。
2. 核对新会话的工具集只包含 `tool-fs` 提供的文件读写能力（read / write / edit / glob），**不含**浏览器、子 Agent、workflow、goal、plan、shell，也不含 `tool-fs-search` / `tool-ask-user` / `tool-todo`（最小重建版已移除）。
3. 属正常现象：**已存在的会话不会切换 Preset**（registry 设计如此），必须新建会话。
4. 若 GUI 中未出现该 Preset，重启 DeepSeek Orb 使其重新加载 profile patch。

## 5. 已知取舍（与设计稿一致）

1. 本 Preset 是 standard 基线的**独立副本**，DSH 升级改动内置 standard 时不会自动合并。
2. 移除了上下文压缩与 tool-result 修剪，超长转写可能触及上下文上限。
3. 移除了 shell，本 Preset 不能执行命令。
4. `complete: true` 使 system prompt 只剩 persona 文本。
